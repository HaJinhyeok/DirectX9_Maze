## 2026-07-19 - 플레이어 충돌 인덱스 경계 분석

### 원인

- `CPlayer::Move()`는 좌우 이동 시 현재 행의 위·현재·아래 세 셀을 `nCoZ - 1 + i`로 조회한다.
- 첫 위치 `(55, 5, -65)`는 마지막 행인 `nCoZ == 13`에 해당하므로 좌우 이동 검사에서 행 14를 조회할 수 있다.
- 앞뒤 이동 시에는 현재 열의 왼쪽·현재·오른쪽 세 셀을 `nCoX - 1 + i`로 조회해, 첫 번째 열에서 열 -1을 조회할 수 있다.
- 오른쪽 경계의 열 12는 배열에 포함된 문자열 종료 문자이지만 플레이 가능한 맵 열은 아니므로 충돌 셀로 조회해서는 안 된다.

### 영향 위치

- `CPlayer.cpp:128`, `CPlayer.cpp:160`: 좌우 이동 시 행 범위 검사 없이 맵 조회
- `CPlayer.cpp:193`, `CPlayer.cpp:224`: 앞뒤 이동 시 열 범위 검사 없이 맵 조회
- 각 분기의 추가 벽 확인도 공통된 안전한 조회 방식을 사용해야 한다.

### 수정 방향

- 행과 열이 각각 `0 <= row < NUM_OF_ROW`, `0 <= column < NUM_OF_COLUMN`인지 확인하는 작은 공통 함수를 `CPlayer.cpp` 구현 영역에 추가한다.

## 2026-07-19 - COM 리소스 해제 공통화 분석

### 원인

- COM 포인터 해제가 `main.cpp`, `CNotice.cpp`, `CSkyBox.cpp`, `XFileUtil.cpp`에 반복되어 있다.
- 대부분 null 검사는 하지만 `Release()` 후 포인터를 null로 돌리지 않아 같은 정리 경로의 재호출에 안전하지 않다.
- 같은 소유 규칙이 여러 형태로 작성되어 새 리소스 추가 시 해제 누락 가능성이 있다.

### 확인한 범위

- `main.cpp`: 전역 메시, 폰트, 텍스처, 버퍼, 디바이스 등 22개 `Release()` 호출
- `CNotice.cpp`: 안내판 버텍스 버퍼 1개 `Release()` 호출
- `CSkyBox.cpp`: 텍스처 배열과 버텍스 버퍼의 2개 `Release()` 호출 지점
- `XFileUtil.cpp`: 메시, 텍스처 배열 원소와 재질 버퍼의 3개 `Release()` 호출 지점
- COM 소유 포인터는 전역 초기값, 생성자 또는 멤버 초기값으로 null 초기화되어 있다.

### 수정 방향

- 새 `ComUtils.h`에 포인터 참조를 받는 템플릿 `SafeRelease(T*& resource)`를 정의한다.
- 포인터가 유효하면 `Release()`를 호출한 뒤 `nullptr`을 대입한다.
- `main.cpp`, `CNotice.cpp`, `CSkyBox.cpp`, `XFileUtil.cpp`의 직접 `Release()` 호출을 공통 함수로 교체한다.
- X 파일 텍스처 배열과 재질 배열은 기존 `delete[]`를 유지하고 배열 포인터도 null로 초기화한다.
- 프로젝트 전체를 `ComPtr`로 전환하는 작업은 전역 상태와 소유 구조를 분리하는 단계에서 검토한다.

### 인접 위험

- `InitD3D()`에서 Direct3D 객체 생성 후 디바이스 생성이 실패하면 현재 `CleanUp()`이 호출되지 않는다.
- `InitGeometry()`의 리소스 생성과 `Lock()` 결과가 검사되지 않아 부분 초기화 실패를 안전하게 복구하지 못한다.
- `CleanUp()`의 일반 포인터 `delete` 경로는 이번 COM 공통화 범위에 포함되지 않는다.
- 위 문제는 `SafeRelease` 적용과 분리해 오류 반환 및 초기화 구조 개선 후보로 남긴다.

### 검증 계획

- 검색으로 직접 `->Release()` 호출이 남지 않았는지 확인한다.
- `SafeRelease`가 모든 포인터를 해제 후 `nullptr`로 만드는지 확인한다.
- `Debug|x86` 빌드에서 경고 0개, 오류 0개를 확인한다.
- 게임 실행 후 일반 종료에서 충돌이나 종료 지연이 없는지 확인한다.

### 상태

- `ComUtils.h`에 `SafeRelease(T*&)` 템플릿을 추가했다.
- `CNotice.cpp`의 안내판 버텍스 버퍼 해제를 `SafeRelease()`로 교체했다.
- `CSkyBox.cpp`의 텍스처 배열 원소 해제를 `SafeRelease()`로 교체했다.
- `XFileUtil.cpp`의 메시와 재질 버퍼 해제를 `SafeRelease()`로 교체했다.
- `main.cpp`의 전역 COM 포인터 22개 해제를 `SafeRelease()`로 교체했다.

### 중간 검증

- `Debug|x86` 빌드에 성공했다.
- 빌드 결과는 경고 0개, 오류 0개다.
- `CSkyBox.cpp`의 버텍스 버퍼와 `XFileUtil.cpp`의 텍스처 배열 원소에 직접 `Release()`가 각각 한 곳 남아 있다.

- `XFileModel`이 널 입력을 거부하고 실제 메시 로드 실패 코드를 반환하도록 변경했다.
- X 파일 텍스처의 직접 경로 로드가 실패하면 모델 경로 기준으로 실제 재시도하고, 텍스처가 없어도 재질 색상으로 렌더링하는 기존 정책은 유지했다.

### 최종 검증

## 2026-07-27 - P4 기능 확장 우선순위 재평가

### 현재 구조에서 확인한 제약

- 미로의 너비와 높이가 `kMazeRowCount`, `kMazeColumnCount`에 고정되어 정점 배열, 충돌, 적 이동과 렌더링이 컴파일 시간 크기에 의존한다.
- 미로 셀은 코드의 전역 문자 배열이며 레벨 파일 로딩, 검증과 전환 흐름이 없다.
- 총알은 이동 거리만으로 제거되고 벽이나 적과 충돌하지 않는다.
- 적은 전역 `Tiger` 한 개로 관리되어 HP, 사망, 다중 스폰과 게임 오버 흐름이 없다.
- 탑뷰는 안내판 접근으로 활성화되지만 숫자 키로도 언제든 전환할 수 있고, 안내판 범위를 벗어날 때 해제하는 경로가 불완전하다.
- 저장소에 포함된 X 파일과 텍스처의 출처·라이선스 문서가 없다.

### 채택

- 외부 미로 데이터는 포트폴리오 가치가 높아 필수 기능으로 채택했다.
- 파일 로더보다 먼저 가변 크기 `MazeDefinition`과 공통 좌표 변환을 도입해 렌더링, 충돌과 AI가 같은 데이터를 사용하도록 한다.
- 총알-벽 충돌은 빠른 투사체의 프레임 간 이동 구간을 검사하는 연속 충돌로 구현한다.
- 총알-적 충돌, 적 HP·사망, 플레이어-적 충돌과 게임 오버를 하나의 전투·게임 상태 흐름으로 묶는다.
- 안내판 범위에서만 탑뷰를 허용하는 규칙을 작은 선행 작업으로 복원한다.
- 레벨별 적 수와 무작위 스폰은 벽, 시작점, 출구와 최소 거리 조건을 만족하는 통로 셀에서 수행한다.
- 기본 게임 규칙은 처치한 적이 해당 레벨에서 다시 생성되지 않는 유한 전투로 정한다.

### 선택

- 절차적 미로 생성은 파일 미로와 같은 `MazeDefinition`을 생성하는 두 번째 데이터 공급자로 구현할 때만 채택한다.
- 생성 결과는 시드로 재현 가능하고 시작점에서 출구까지 도달 가능해야 한다.
- 격자 기반 경로 탐색은 새 모델 없이도 AI와 자료구조 역량을 보여줄 수 있어 선택 기능으로 추가한다.
- 다중 적 경로 탐색은 매 프레임이 아니라 플레이어 셀 변경 또는 제한된 주기로 갱신하고 성능을 측정한다.

### 제외 또는 보류

- 외부 X 파일을 추가해 적의 외형 종류만 늘리는 작업은 기술적 차별점이 작고 에셋 탐색·라이선스 비용이 커 필수 범위에서 제외한다.
- 적 수를 무한히 유지하는 자동 리스폰은 탐색 진행감을 약화하고 난이도 근거가 없으므로 기본 규칙에서 제외한다.
- 리스폰 정책은 유한 전투 플레이 테스트 후 압박감이 부족할 때 레벨 데이터 옵션으로 재평가한다.

### 추가한 포트폴리오 작업

- 모델과 텍스처의 출처·라이선스 확인을 기능 추가보다 먼저 수행한다.
- 미로 로더, 좌표 변환, 생성과 충돌을 Direct3D 실행 없이 검증할 수 있는 자동 검증 대상을 추가한다.
- 대표 맵 크기와 적 수별 frame time을 측정해 기능 추가의 비용을 수치로 남긴다.
- 마지막에 핵심 기술과 개선 전후 근거를 README에 반영하고 `Release|x86` 실행 패키지를 검증한다.

### 추가 결정 - 탑뷰

- 플레이 규칙의 탑뷰와 개발 검증용 탑뷰를 같은 입력 상태로 취급하지 않는다.
- 플레이에서는 안내판 상호작용 범위 안에서만 탑뷰를 활성화하고 범위를 벗어나면 해제한다.

### 추가 조사 - 프러스텀 컬링

- `Frustum::IntersectsSphere()`의 `평면 거리 < -반지름` 조건은 경계 구가 한 평면 바깥에 완전히 놓였을 때만 제외하는 보수적인 판정으로 적절하다.
- 현재 각 평면의 법선 길이를 모든 물체 판정에서 다시 계산하므로 프러스텀 갱신 시 평면을 한 번 정규화하는 편이 낫다.
- 바닥과 벽 면은 축 정렬된 정사각형이므로 경계 구보다 AABB가 빈 공간을 덜 포함해 더 정확한 판정을 제공한다.
- 기존 탑뷰에서 플레이어 1인칭 프러스텀을 사용하는 것은 탑뷰 화면으로 플레이어 시점의 컬링 결과를 관찰하려는 의도였다.
- 다만 같은 탑뷰 상태를 안내판 힌트에도 사용하므로 플레이 기능과 개발 검증 목적을 구분하지 못한다.
- `NoticeHint`에서는 렌더링과 컬링 모두 탑뷰 카메라를 사용하고, `CullingDebug`에서는 탑뷰로 렌더링하면서 플레이어 카메라 프러스텀을 유지한다.
- 한 타일의 두 삼각형은 한 번의 `DrawPrimitive()` 호출로 함께 제출되므로 삼각형별 CPU 컬링은 드로우 콜과 판정 비용을 늘리는 데 비해 절약하는 정점 수가 작다.

## 2026-07-27 - P4-03 Notice 기반 탑뷰 규칙과 개발용 전환 분리

### 시작

- P4-02 완료 후 Roadmap의 `P4-03`을 진행 중으로 변경했다.
- 플레이 기능인 안내판 힌트와 개발 중 컬링 확인 기능이 `g_isTopViewEnabled` 하나를 공유하는 현재 흐름을 조사한다.

### 현재 구조 조사

- 숫자 `2` 입력과 Notice 접촉이 모두 `g_isTopViewEnabled`를 직접 변경한다.
- Notice 접촉 시에는 상태를 `TRUE`로 바꾸지만 범위를 벗어날 때 `FALSE`로 복구하는 경로가 없다.
- 카메라, UI, 탑뷰 플레이어 표식과 마우스 회전 차단도 모두 같은 bool을 참조한다.
- 탑뷰 활성화 이유를 `Disabled`, `NoticeHint`, `CullingDebug`로 구분하는 상태가 필요하다.
- 개발용 전환은 Debug 빌드에서만 처리하고 조작 안내 UI에는 노출하지 않는 방향으로 진행한다.

### 구현

- `g_isTopViewEnabled` bool을 `Disabled`, `NoticeHint`, `CullingDebug`를 갖는 `TopViewMode`로 교체했다.
- 카메라, UI, 플레이어 표식과 마우스 회전 조건은 `IsTopViewActive()`로 공통 조회한다.
- Notice 범위 안에서는 `NoticeHint`, 범위를 벗어나면 `Disabled`로 갱신하되 `CullingDebug`는 접촉 상태와 무관하게 유지한다.
- 개발용 탑뷰 전환을 Debug 빌드의 `F2`로 옮기고 인게임 조작 안내에서는 제거했다.
- README에는 `F2`가 Debug 빌드 전용 컬링 확인 기능임을 명시했다.
- 기능 입력을 상호작용 갱신보다 먼저 처리해 Debug 탑뷰를 끈 프레임에 Notice 상태가 즉시 반영되도록 했다.

### 검증

- 처음에는 `#ifdef DEBUG`를 사용해 Visual Studio Debug 구성에서도 F2 코드가 컴파일되지 않았다.
- 프로젝트 설정에 정의된 실제 매크로인 `_DEBUG`로 수정한 뒤 F2 전환이 정상 동작함을 사용자가 확인했다.
- `Debug|x86` 빌드가 경고 0개, 오류 0개로 성공했다.
- 사용자가 Notice 진입 시 탑뷰 전환, 이탈 시 1인칭 복귀를 확인했다.
- `CullingDebug` 상태가 Notice 이탈 후에도 유지되고, Notice 범위 안에서 F2를 끄면 `NoticeHint`로 전환된 뒤 이탈 시 해제됨을 확인했다.

### 완료

- 플레이 기능과 개발용 탑뷰가 활성화 이유에 따라 분리되고 Debug 입력이 Release 빌드에서 제외되어 P4-03을 완료로 변경했다.

## 2026-07-28 - P4-06 외부 미로 파일 로더와 검증

### 시작

- Roadmap의 `P4-06`을 진행 중으로 변경했다.
- 현재 코드에 포함된 기본 미로의 생성 위치와 `MazeDefinition` 초기화 경로를 확인했다.
- 외부 레벨 파일 하나가 셀과 플레이어·적 시작점, 출구, 안내판 위치를 함께 표현하도록 문자 기반 형식을 사용한다.
- 행 끝 공백이 편집 과정에서 손실되는 문제를 피하기 위해 빈 통로는 공백 대신 `.`으로 표현한다.

### 레벨 파일과 로더

- `Assets/Data/Levels/Level01.txt`에 기존 12x14 미로를 외부 데이터로 옮겼다.
- `*`는 벽, `.`은 통로, `P`는 플레이어 시작점, `T`는 호랑이 시작점, `X`는 출구, `@`는 안내판으로 정의했다.
- `MazeLoader`가 파일 열기와 읽기 실패, 빈 파일, 빈 행과 행 너비 불일치를 검사하도록 구현했다.
- 허용되지 않은 문자를 파일·행·열·문자 값과 함께 보고하도록 구현했다.
- `P`, `T`, `X`는 정확히 하나만 허용하고 중복과 누락을 거부하며, `@`는 여러 좌표를 수집하도록 구현했다.
- 마커 좌표를 `MazeDefinition`으로 옮긴 뒤 셀 문자를 `.`으로 정규화해 런타임 셀에는 벽과 통로 정보만 남겼다.

### 런타임 전환

- 프로그램 초기화 시 외부 레벨 파일을 먼저 읽어 `g_maze`를 구성하도록 연결했다.
- 플레이어·호랑이 시작점, 내부 벽, 바닥, 외곽 벽, 안내판, 출구와 이동 충돌이 모두 로드된 `g_maze`를 사용하도록 전환했다.
- 하드코딩된 `kDefaultMaze`와 `MazeData.h/.cpp`를 제거했다.
- 레벨 로딩 실패 시 일반 초기화 실패 문구 대신 로더의 상세 오류를 메시지 창에 표시하도록 변경했다.

### 검증
