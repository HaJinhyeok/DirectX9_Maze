# 개선 전후 근거

## 기준

프로젝트 작업 문서 체계를 처음 정리한 커밋 `b177664`을 개선 전 기준선으로 사용한다. 당시에도 `Debug|x86` 빌드와 기본 게임 실행은 가능했지만 고정 크기 문자 배열, 한 개의 단순 이동 적, 수동 검증 중심 구조와 불완전한 실패 처리가 남아 있었다.

이 문서는 이후 변경을 단순 기능 목록이 아니라 `기존 문제 → 선택한 해결 → 검증 근거 → 남은 한계` 순서로 정리한다.

## 주요 선택과 근거

### 책임 분리와 컨벤션

- **문제:** 클래스·함수·전역·상수 이름이 서로 다른 규칙을 사용했고 `main.cpp`, `main.h`, `XFileUtil`에 여러 책임이 모여 변경 영향을 추적하기 어려웠다.
- **선택:** 동작을 유지한 채 네이밍을 먼저 통일하고, 입력·게임 갱신·렌더링, 모델 리소스, 미로 데이터·메시, 플레이어 충돌을 작은 단계로 분리했다.
- **근거:** 각 단계에서 `Debug|x86` 전체 빌드를 확인했고 최종 소스는 [`CODING_CONVENTIONS.md`](CODING_CONVENTIONS.md)의 규칙을 따른다.
- **관련 이력:** `39ab18a`, `532d8e7`, `e5226b5`, `aea699a`, `16be882`, `4995229`

### 안정적인 Direct3D9 수명 관리

- **문제:** COM 포인터 해제 중복, 생성·Lock 실패 후 null 또는 부분 리소스 사용 위험, 창 크기 변경과 종료 경로의 상태 불일치가 있었다.
- **선택:** 해제 후 null을 보장하는 공통 함수와 managed 버퍼 업로드 경로를 만들고, 실패 시 부분 생성물을 정리했다. 창 크기 변경은 백버퍼와 폰트 리소스를 Direct3D9 규칙에 맞춰 리셋하며 게임 종료는 `WM_CLOSE` 경로로 통일했다.
- **근거:** 필수 텍스처를 임시로 누락했을 때 오류 안내 후 예외 없이 종료됐고, 창 이동·크기 조절·일시정지·종료를 수동 검증했다.
- **관련 이력:** `3ae37f5`, `27d48a2`, `310451f`, `bae9956`

### 데이터 기반 레벨 확장

- **문제:** 미로가 코드의 단일 고정 배열이어서 크기와 콘텐츠를 바꾸려면 컴파일이 필요했고 메시 생성, 충돌과 적 이동이 고정 상수에 의존했다.
- **선택:** 셀, 크기와 주요 마커를 보관하는 `MazeDefinition`을 중심 데이터로 두었다. 외부 파일 로더와 절차 생성기는 검증 후 같은 정의를 반환하며 레벨 목록이 미로 출처, 적 수와 시드를 관리한다.
- **근거:** 행 너비, 잘못된 문자, 필수·중복 마커, 카탈로그 형식과 시드 재현을 자동 테스트하고 서로 다른 크기의 세 레벨을 실제 전환했다.
- **관련 이력:** `4324dd7`, `300dc89`, `b95d918`, `d4cb337`, `8548faa`

### 연속 충돌과 게임 루프

- **문제:** 위치를 한 프레임씩 이동한 뒤 검사하는 방식은 빠른 투사체가 얇은 벽이나 적을 건너뛸 수 있고, 벽 뒤 적과의 충돌 순서를 구분할 수 없다.
- **선택:** 투사체의 시작점과 끝점 사이에서 벽의 확장 AABB와 적의 확장 구체를 sweep하고 정규화된 최초 충돌 시각을 비교했다. 플레이어는 X·Z축을 따로 보정해 벽 미끄러짐과 모서리 안정성을 확보했다.
- **근거:** 벽 관통, 경로 밖 벽, 외벽, 구체 초기 겹침과 최초 충돌을 자동 테스트하고 적 HP·사망·게임 오버·재시작을 실행 검증했다.
- **관련 이력:** `9ecf340`, `ca747c6`, `c634f6c`

### 공유 경로 탐색과 다중 적

- **문제:** 단일 적의 난수 이동은 플레이어를 추적하지 못하고 적마다 별도 BFS를 수행하면 적 수에 비례해 전체 미로 탐색이 반복된다.
- **선택:** 플레이어 셀에서 역방향 BFS 거리 필드를 한 번 만들고 모든 적이 공유한다. 플레이어 셀이 바뀔 때만 다시 만들며 각 적은 네 이웃 중 거리가 감소하는 셀을 선택한다.
- **근거:** 거리 필드와 다음 셀 선택을 자동 테스트하고 다중 적 추적을 실행 검증했다. 같은 21 x 17 미로에서 적을 3마리에서 30마리로 늘렸을 때 평균과 p95 frame time은 약 10% 증가했다.
- **관련 이력:** `ec2eedd`, `2e39b28`, `c17a8eb`

### 검증 체계와 포트폴리오 근거

- **문제:** 최초 기준선은 빌드와 육안 실행 확인만 있어 오래된 프로젝트를 수정할 때 회귀를 빠르게 찾거나 성능 주장을 재현하기 어려웠다.
- **선택:** Direct3D 장치 없이 실행 가능한 데이터·좌표·충돌·생성·경로·통계 로직을 콘솔 테스트 프로젝트에 모았다. 그래픽스와 입력은 별도 스모크 테스트로 관리하고 성능은 고정 워밍업·수집 구간과 p95를 사용했다.
- **근거:** 자동 테스트 40개가 통과하며 수동 절차는 [`SMOKE_TEST.md`](SMOKE_TEST.md), 성능 조건과 수치는 [`PERFORMANCE.md`](PERFORMANCE.md), 에셋 공개 근거는 [`ASSET_LICENSES.md`](ASSET_LICENSES.md)에 기록되어 있다.
- **관련 이력:** `cc459c8`, `b95d918`, `83e3bb7`, `c17a8eb`, `4a97b3c`

## 남아 있는 한계

- `main.cpp`에 Direct3D 초기화, 레벨 전환, 렌더링과 전역 게임 상태가 여전히 많이 모여 있다.
- 적 인스턴스마다 동일한 X 파일 모델 리소스를 개별 로드하므로 더 큰 적 수에서는 공유 모델 리소스가 필요하다.
- 구체와 AABB 중심의 단순 충돌 경계는 실제 X 모델 외곽과 정확히 일치하지 않는다.
- 자동 테스트는 순수 로직에 집중하며 Direct3D 장치 손실·복구, 실제 렌더링과 입력은 수동 검증에 의존한다.
- 성능 결과는 한 PC의 `Debug|x86`에서 측정했으며 CPU와 GPU 비용을 분리하지 않았다.
- `Release|x86` 빌드와 새 환경 실행 패키지 재현은 아직 검증 전이다.

이 한계는 숨기지 않고 [`ROADMAP.md`](ROADMAP.md)의 후속 작업과 README의 현재 한계에 유지한다.
